# Porting map from aia-mp1-synthetic-data

This maps every Python module, test file and tool in the earlier **aia-mp1-synthetic-data** repository onto the `bonsai_help` package. It is a planning record. Only the generic BM25 core of `retrieval.py` has been ported so far, into `docs_index` at B2 (see §3.5 and §8). Section references (§) point to the adaptation plan, `MP1-BONSAI-HELP-CHATBOT.md` (see `DECISIONS.md` for the edits Chad directed to it). Counts were checked against the earlier repository's tracked files on November 21, 2026.

**Overrides plan §8 (Repository).** The plan proposed adding a `bonsai-help` domain inside the old repository. This project starts a new, clean repository instead (O-4, see `DECISIONS.md`). Selected code is ported into a new history. The old repository's history, evidence, prompts, rubrics, fixtures and configuration are not imported. Ported modules are rewritten as needed and only ever take synthetic or open-licensed data.

**B0 scope (the assistant's call).** No old module is copied in B0. The modules are tightly coupled to the old domains, so B4 ports them module by module, each with its tests. The plan's B4 criterion "existing suite still passes" becomes "each ported module arrives with its tests passing". §8 below gives the order.

## 1. Decisions at a glance

| Decision | Python modules | Meaning |
| --- | ---: | --- |
| CARRY | 7 | Generic pipeline code. It moves over with only the cross-cutting changes in §2. |
| ADAPT | 21 | Carried, with the specific changes named in §3. |
| LEAVE | 50 | Specific to AEC, home-DIY, engineering, recovery, fact-checking, rubric v2, the hosted "frontier" judge or a machine-specific workflow. Not ported. A few are listed as design references only. |
| **Total** | **78** | Includes `__init__.py` and `__main__.py`. |

The old test suite has 86 test files plus 4 fixture modules. Tests are ported as **behaviour tests**: each is rewritten against synthetic Bonsai fixtures and keeps the property it asserts, not its literal data (§5). Of the 81 tool files (scripts and shell helpers), 5 are adapted, 2 are kept as references and 74 are left (§6).

## 2. Cross-cutting changes for every carried module

1. **No domain switch.** Delete `AIA_MP1_DOMAIN`, `schemas.DOMAIN` and every `if DOMAIN == ...` branch. The new package has one domain. Its five categories are one `Literal` in `schemas.py` (§5 of the plan; open item O-2): `bonsai_project_setup`, `bonsai_modeling`, `ifc_data_and_materials`, `model_exploration`, `files_versions_troubleshooting`.
2. **Package rename** from `aia_mp1` to `bonsai_help`. `generate.implementation_identity()` hard-codes `src/aia_mp1`; derive the path from `__package__` instead. The console script `aia-mp1` becomes `bonsai-help`.
3. **Environment variables**: `AIA_MP1_API_KEY` becomes `BONSAI_HELP_API_KEY`, and `AIA_MP1_TOOLS` becomes `BONSAI_HELP_TOOLS`.
4. **Paths.** Remove the old default artifact root (a folder outside the repository named after a program ID) and any program IDs. Use a configurable root, defaulting to a git-ignored `runs/` folder or a path outside the repository. Remove the hard-coded rubric paths (`config/aec-course/...`, `config/diy/...`) and the pinned AEC rubric digest in `assessment.validate_rubric`. The new rubric is `config/rubric.json`, pinned by its own hash.
5. **Submission exception (O-5, decided).** Today `config.external_artifacts`, `assessment.assessment_directory`, `analysis.output_directory` and `collection.collection_directory` reject any path inside the repository. Keep that rule for raw runs. Add one explicit exporter that copies the final, hash-verified submission set into `submission/` (§4, item 14).
6. **Endpoint policy (plan §8 Models).** `RunConfig.local_endpoint` accepts only localhost or private IPs. Keep that as the default. Add an opt-in hosted, OpenAI-compatible profile that needs three things: an explicit `hosted: true`, a recorded authorization reference and a cost cap. Never fall back to a hosted model silently.
7. **Authority strings.** Remove the owner names, owner-policy amendments and dated decision records hard-coded in code (`acceptance.OWNER_POLICY`, `retrieval.PACK_APPROVED_BY`). Thresholds come from the pinned rubric. Any later amendment is a dated entry in `DECISIONS.md` plus a policy ID.
8. **Python floor.** The old `pyproject.toml` requires 3.12 or newer; the plan says 3.10 or newer. B0 keeps 3.12 and documents it. Run the ported tests on 3.10 before lowering the floor. Dependencies carry over: pydantic, instructor, openai and httpx; matplotlib and seaborn for analysis; pytest and ruff for development. Add pypdf only if `assessed_review` is ported.
9. **Fixtures.** All test data is new and synthetic, or taken from the committed open-licensed fixture slice (§2 of the plan). No old fixture content is copied.
10. **Import cycles.** The old code has two cycles, each closed by a function-level import. (a) `collection` imports `cli.gate_run`, while `cli` imports `collection_cli`, which imports `collection`: move `gate_run` into the gate layer. (b) `assessment` imports `cohort.load_cohort`, while `cohort` and `collection` import `assessment` at module level only for its file helpers `exclusive`, `read_json`, `read_text` and `save_new`: move those helpers into `tracing`. After both moves `collection` and `cohort` no longer import `assessment` or `cli`, and `assessment` imports `cohort` at module level.

## 8. Port order by milestone

Each milestone ports only modules whose internal imports are already ported, so "each module arrives with its ported tests passing" holds at every step. Test cases that need a later module (for example the `test_collection.py` cases for `human_reference`) arrive with that module.

- **B0 (done)**: new repository skeleton, `LICENSE`, README skeleton, decision log, the owner's plan, this map, the packaging and test configuration. No module is ported (see the B0 scope note above).
- **B1 (done)**: snapshot builder and checker (new code; `git_blob_id` is reimplemented in `git_fetch`).
- **B2 (done)**: `docs_index` (the BM25 extract, with section records cut at RST headings), lexicon extractors, setup profiles and fact table. Deviations from §3.5 (the assistant's calls, see `DECISIONS.md`):
  - `segments_rst_sections` is superseded by a general splitter (docutils adornment rules; one record per heading; the records of a page concatenate to its bytes).
  - `n1` is not ported: every pinned page is strict UTF-8 without BOM or CR, and a page that is not is refused, so spans equal upstream. `g5_tokens` and `ngrams` are deferred to B3's leakage check, their only consumer, with their tests.
  - `git_blob_id` stays in B1's `git_fetch`; `write_new` is B1's writer, made public.
  - `chunk_segments`/`finalize_chunks` become `passages`/`finalize_passages` over section records (no live-code removal; identical text collapses per source). Ranking drops the identifier bonus, `m` and the floor, which B5's retrieval policy owns; the tie-break is score, source order, path, span, key. Passage size is a whitespace word count (no tokenizer dependency).
  - Ported tests: golden terms (rewritten for Bonsai strings), stopwords, golden BM25, hash-seed stability (rewritten), every tie-break level and rounding (rewritten for the new key), both window tests, verbatim reslice and finalize (rewritten). The `test_n1_*` and `test_g5_*` tests are deferred with their code; `test_git_blob_id_matches_git` is covered by B1. New: splitter cases, index build and check, the missing-section case (`docs section` is exit 1).
- **B3**: gold-set format and pattern scorer.
- **B4**: in dependency order, `tracing` (with the file helpers from `assessment`), `schemas`, `evaluation_schemas`, `sources` (snapshot manifest), `config`, `model_client`, two-stage `generate`, the Bonsai `gate` checks with embedding duplicate removal (with `gate_run` from `cli`), `collection`, `cohort`, and the generation commands of `cli` and `collection_cli`; each module arrives with its ported tests passing.
- **B5–B6**: the doc tools and chatbot loop, `assessment` (blind mixed arm), `labels`, `human_reference`, and the assessment and labeling commands of `evaluation_cli`.
- **B7**: `judge` v1 and v2, `qualification`, `acceptance`, the `stats` extract from `compare_human` (Clopper–Pearson is needed by calibration), `calibration` with TPR/TNR and intervals, and the judge and calibration commands of `evaluation_cli`.
- **B8–B9**: `analysis` (paired; McNemar added to `stats`), `analysis_export` (five charts), `analysis_cli`, security pass.
- **B10**: `submission/` exporter, replay demo, iteration log.
